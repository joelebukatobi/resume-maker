# Native UI rebuild — plan

Rebuild the frontend to `DESIGN.md` without changing backend logic. The design
reference is the **Design** page of the Resume Maker canvas.

## The one rule

No change to backend logic: no API, endpoint behaviour, model, prompt, fill,
library or protocol change. The only server change allowed is routing that
serves the new frontend files, and it is security-first.

## Slices

Each slice ends green on `python3 -m unittest discover -s tests` and is its own
commit.

1. **Foundations.** A locked-down `GET /static/ui/<name>` route: one folder,
   `.css` and `.js` only, names matching `^[a-z0-9][a-z0-9-]*\.(css|js)$`, the
   resolved path checked to sit inside `static/ui/`, fixed content types.
   `static/ui/tokens.css`, `reset.css` and `atoms.css` carry DESIGN.md. Tests
   prove traversal, other extensions, dotfiles and unknown names are refused.
2. **Shell.** `<app-nav>` and `<step-strip>` as light-DOM custom elements, the
   theme toggle persisted per browser, the layer tokens. First page to adopt
   them: Voice.
3. **Standing pages.** Applications (`/`), Voice, Notes, each with its
   whole-file view, against the existing setup and apps APIs.
4. **Workbench steps.** `index.html` becomes the six steps. The section round
   that `chat.js` drives today moves into a step controller that calls the
   same endpoints in the same order; the chat pane opens only after Review.
5. **Changes and Review.** The paper preview, checks, downloads, and the
   change pane with the existing chat endpoint.
6. **Settings and retirement.** Settings as a page, the theme editor moved
   there; Pico, `base.css`, `chat.css` and the old markup removed once nothing
   loads them.

## Not in scope

Backend logic of any kind; the CV renderer and theme files; the landing page.
